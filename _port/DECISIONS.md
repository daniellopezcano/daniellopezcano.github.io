# Decisions

Each decision has the reason that led to it, so that a later session (possibly on a different model) can apply it without asking. Change a decision only if it blocks you; record the change and the reason here.

## Architecture

**D1. Quarto website, not a Quarto book; the converter resolves every cross-reference itself.**
Quarto's native cross-references across pages only work in book projects, and its numbers are Quarto's, not LaTeX's. The site must stay one website project, and numbers must be the PDF's. So the converter knows where every `\label` lands (page + anchor) and writes plain links carrying the number taken from LaTeX (D5). Nothing depends on Quarto's `@ref` machinery.

**D2. Course lives in `notes/diffgeo-gr/`; addresses come from the LaTeX labels, not from numbers or titles.**
`\chapter{Vector Spaces}\label{chapter_Vector_Spaces}` → `notes/diffgeo-gr/vector-spaces/index.html`; `\section{…}\label{section_Foundations_Sets_Maps}` → `…/vector-spaces/foundations-sets-maps.html` (prefixes `chapter_`, `appendix_`, `section_`, `subsection_` are dropped; a heading without a label falls back to its title). Numbers shift when a chapter is inserted (Symmetries will become Ch. 9) and titles get reworded; labels are the stable name the author already maintains. `COURSE` in `build.py` is the one place that names the directory.

**D3. One page per chapter opening and one per `\section`.** The chapter page holds the motivation box and the text before the first section, then a generated list of its sections. Subsections are headings inside the section page and feed "On this page". Appendix B and C sections (one proof / one worked example each) are pages too. This gives 76 pages of 1–6 screens; chapters as single pages would be 10–25 screens with hundreds of formulas each.

**D4. Own strict converter (`_port/convert/`), Python standard library only; pandoc's LaTeX reader is not used.**
Reasons: (a) pandoc rewrites math (`align*` → `aligned`, expands macros) while rule 3 wants the source untouched; (b) pandoc silently drops what it does not know, while we need the opposite: every command and environment is declared in `texparse.py` and handled in `render.py`, anything else stops that page with `file:line` ("teach the converter"); (c) the notes use a small regular subset (lists, footnotes, figures, boxes, colour macros), so a recursive-descent parser is ~400 lines; (d) emitting HTML directly avoids Markdown escaping bugs. Math is never parsed: it is captured as the exact source string.
Pipeline: `source.py` (strip comments like TeX does, expand uncommented `\input`, keep file:line for every character) → `texparse.py` (nodes) → `render.py` (HTML with placeholders) → `build.py` (page map, numbering, link resolution, `.qmd` files, sidebar, landing-page fragments).
Files that `main.tex` does not include are never opened, which is how "publish exactly what main.tex includes" holds; including them later needs no converter change.

**D5. Numbers come from an instrumented LaTeX build, keyed by source position.**
`_port/tex/build_scratch.sh` copies the notes to `_port/.work/tex/stage`, injects `\input{port-hooks}` on the `\begin{document}` line (so no line shifts), compiles with latexmk/XeLaTeX and publishes the result to `_port/.work/tex/src` only on success. `port-hooks.tex` typesets nothing; it writes `main.port`, one line per numbered object in source order: `counter|printed number|file|line` (hooks on `\refstepcounter`, on the caption package's `\caption@@refstepcounter`, and on `\H@@footnotetext` for footnotes incl. `\footnotetext[n]`). `build.py` assigns each record to the page whose source span contains it and the renderer consumes them in order; a page fails if LaTeX numbered something the converter did not see, or the reverse. `\ref` numbers and kinds come from `main.aux`. Verified: the scratch build's labels are identical to the notes' own `main.aux`, and `pdftotext` of both PDFs differs only in the date.
Never compute a number in the converter. If a new kind of numbered object appears (e.g. `table`), it will already be in `main.port`; add the `take('table')` call.

**D6. Output is `.qmd` whose body is raw HTML blocks; in-page headings are Markdown headings with raw-inline content.**
Quarto builds the "On this page" outline and the search index from real headings, so `\subsection`s are written as `## `<span class="dg-secnum">7.2.1</span> Title`{=html} {#label}`; everything else is in ```` ```{=html} ```` blocks. No pandoc Math nodes are ever produced (math is `<span class="math inline">\(…\)</span>` in raw HTML), so pandoc never touches the equations. Quarto's own title block is hidden by CSS and the page header (`.dg-head`: kicker "Chapter 2 • Vector Spaces" as in the PDF running header, then the numbered title) is generated from the notes. The YAML `title` is kept for the browser tab, sidebar and search.

**D7. Math: MathJax 3.2.2 (CHTML), one shared configuration, source verbatim.**
`notes/diffgeo-gr/assets/mathjax-config.js` is the single math configuration. The notes' preamble defines no math macros, so the config only holds what MathJax lacks (`\xlongrightarrow`) and the font switches (D8). Quarto loads MathJax itself on every page; `_metadata.yml` pins the URL and `_head.html` puts our config before it. The only rewrites of math source, all forced by the web, are in `render.py: Renderer.math`: (1) `\label{x}` in a numbered environment → `\tag{n}` with LaTeX's number, (2) `\ref`/`\eqref` inside math → the number, (3) `\hyperlink{t}{…}` → `\href{#t}{…}`, (4) macros `\edef`'ed to a footnote number (Ch. 8) → that number. Every expression is test-typeset at build time by `_port/tools/math_check.mjs`. (Engine comparison and any config fixes: see "Measured" below.)

**D8. Runic symbols: the literal Unicode rune, the notes' own font, restricted to the runic block.**
The source writes `\textrm{\runic ᛊ}`. On the web `\runic` (and `\cunei`) expand to nothing and the rune stays a Unicode character inside `\textrm{}`; `course.css` declares `@font-face "Noto Sans Runic"` from the notes' `fonts/NotoSansRunic-Regular.ttf` (copied by the converter, 10 kB) with `unicode-range: U+16A0-16FF`, MathJax's `unknownFamily` names it, and `startup.pageReady` waits for `document.fonts.load` so the widths MathJax measures are the real glyph's. Result: same glyphs as the PDF on any machine, in inline, display, sub- and superscripts. TikZ pictures get their runes as outlines from the same font (D10).

**D9. Print-only layout commands are dropped; vertical rhythm is kept.**
`\noindent`, `\vspace`, `\newpage`, `\clearpage`, `\thispagestyle`, `\addcontentsline`, float placement options and the running-header title of `custompage` have no meaning on a web page and produce nothing. `\smallskip/\medskip/\bigskip` become spacing classes because the author uses them to group paragraphs. TeX input conventions are mapped to what the PDF shows: `` `` ''`` → “ ”, `--` → –, `---` → —, `~` → no-break space, `\S` → §.

**D10. Figures.** (a) `plots/*.pdf` → SVG when small, otherwise WebP at 2400 px (thresholds and tools in `figures.py`; measured table below). (b) Every TikZ picture is compiled from the author's source: the figure body goes into a standalone document with the notes' preamble verbatim and the right `\textwidth` (16 cm, or the `custompage` width for roadmaps), `main.aux` is supplied so `\ref` resolves, XeLaTeX → `.xdv` → `dvisvgm --no-fonts` (glyphs as outlines, so no font dependence). Nothing is redrawn. (c) In those builds `\ref` is wrapped so that each reference becomes `<g class="dg-xref" data-label="…">` in the SVG; the page script turns them into links using `assets/labels.json`. (d) Figures keep their own light background and sit on a white "paper" card at the same fraction of the text width as in the PDF (`--dg-frac`); no colour inversion, because the colours carry meaning. (e) Click opens a zoom/pan viewer. Outputs are cached by content hash in `_port/.work/figcache` and written to `notes/diffgeo-gr/figures/`.

**D11. Footnotes** keep LaTeX's numbers (per chapter), are listed at the foot of the page that cites them, and open in a popover on hover/focus/tap.

**D12. Colours.** The eleven term colours keep their meaning; the dark `_1` shades are lightened for the dark page, the `_2` shades are kept. The mapping is the `--dg-color-*` table at the top of `course.css`; `\textcolor{color_x_n}` maps to the same variables. Unknown colour names stop the page.

**D13. Reading surface.** Course pages load `assets/course.css` (only they do), which removes the animated background, sets a solid `--dlc-bg` surface and a 780 px text column, and uses its own Quarto `grid`. Cost: Quarto compiles one more Bootstrap bundle for the different grid (0.5 MB in `docs/site_libs`, ~75 kB over the wire). Accepted because overriding Quarto's grid in CSS breaks between Quarto versions.

**D14. Web layer.** Everything not in the PDF carries class `dg-web` (navigation aids) or sits in a `dg-interactive` frame with an "Interactive" badge. Every word written for it is listed in `REVIEW.md`. Prev/next links and the section list of a chapter are generated by the converter (no site-wide `page-navigation`).

**D15. Interactive figures.** Mapping in `_port/interactives.json` (`label` → `module`); the converter emits an empty frame right after the figure or heading with that label. `course.js` lazily imports `assets/interactive/<module>.js` when the frame nears the viewport; each module exports `default function mount(body, frame)` and imports the shared `assets/interactive/dg.js` (controls with MathJax-rendered labels, a 2D SVG plot helper, a small canvas 3D scene with painter's-algorithm surfaces, the palette). No third-party library. Budget (raw, unminified): `dg.js` ≤ 35 kB (≈ 11 kB gzipped), each module ≤ 20 kB, data ≤ 150 kB per figure; all loaded only on pages that have a frame, and only when the frame nears the viewport. Modules and `labels.json` are fetched at run time, so they are listed under `project: resources` in `_quarto.yml` (Quarto only copies what the HTML references). A frame that has not mounted is collapsed (`height:0; visibility:hidden`, not `display:none`, which would never intersect the viewport and so never load). Quarto moves every `<aside>` to the margin column; `interactive.css` puts `aside.dg-interactive` back in the body column. The pattern to follow for new interactives is `maps.js` (2D) and `variations.js` (3D + plot); the API of `dg.js` is documented at the top of that file. Geometry is computed in JS when the formulas are in the notes (they usually are, in Appendix C); only where a figure's geometry exists solely in the Python package is it exported offline to JSON. If JS fails the frame stays hidden and the static figure is untouched.

**D16. Partial conversion is visible, strict mode is the goal.** `build.py` writes the pages that convert, lists the others as `PENDING <file:line>: reason`, shows them greyed out in the sidebar and renders references to them as unlinked numbers. `build.py --strict` (used by `check.sh`) fails if any page is pending.

**D17.** References whose label does not exist in the build ("??" in the PDF) render as a small "in preparation" marker. **D18.** `\DLC{…}` author notes render nothing and are listed in `REVIEW.md`. Typos are never fixed.

**D19. Landing page.** `index.qmd` is hand-written and includes generated fragments from `notes/diffgeo-gr/_generated/` (cover texts, quote and dedication, contents, master roadmap). `cover.py` extracts the texts from the TikZ nodes of the title and dedication pages with anchored patterns that fail loudly if `main.tex` is restructured.

**D20. Bibliography** page and citation texts come from `main.bbl` (natbib author–year), so they match what BibTeX produced.

## Working rules

**D21. Scratch and environments.** Everything temporary is under `_port/.work/` (git-ignored): `tex/stage`, `tex/src`, `figs`, `figcache`, `report.json`. Node tools live in `_port/node_modules` (git-ignored; `_port/package.json` is committed). The converter needs only Python ≥ 3.10 stdlib. This machine has no `python3-venv`; if the Python package must run (data export), use a conda prefix env at `_port/.env`.

**D22. Git.** The working tree shows ~120 files as modified because of file-mode changes only (`old mode 100644 / new mode 100755`); never `git add -A` or `git commit -a`. Stage explicit paths: `_port/`, `notes/`, `docs/notes/`, `docs/site_libs/`, `docs/search.json`, `docs/sitemap.xml`, `_quarto.yml`, `.gitignore`, `CLAUDE.md`, `.claude/agents/`, and the `docs/*.html` of existing pages only when their content (not mode) changed.

**D23. Generated vs hand-written.** Generated (never edit): `notes/diffgeo-gr/**/*.html` (every page, the landing page included; D29), `assets/search.json`, `assets/labels.json`, `assets/fonts/` (the NewCM WOFF2 subsets; `NotoSansRunic-Regular.ttf` there is the notes' own font file, committed as is), `figures/`, `docs/`. Hand-written: `assets/*.css|js` (`course.css`, `interactive.css`, `course.js`, `mathjax-config.js`), `assets/interactive/`, `_port/interactives.json`, all of `_port/convert` (including the page shell `shell.py` and the landing-page template `templates/landing.html`), `_port/tex`, `_port/tools`. Since R9 the converter also writes `notes/diffgeo-gr/assets/lastmod.json` (generated; the last time each page's bytes changed, read by `post_render.py` so that the sitemap is stable across rebuilds).

**D26. Things Quarto does to raw HTML that the converter must avoid** (found in the pilot review). (a) `<aside>` is moved to the margin column and its ancestors (`<li>`!) get grid classes that drop list markers: web-layer frames are `<div role="group">`. (b) `<section role="doc-endnotes">` and `role="doc-noteref"` trigger Quarto's own footnote appendix and popups: footnotes are plain `<div class="dg-footnotes">`, and `_metadata.yml` sets `footnotes-hover: false`. (c) A title that contains a cross-reference must not be placed inside another link (prev/next, section lists, contents, kicker): `build.py: nolinks()` turns its references into plain numbers there. (d) A site with a sidebar gets a border above the page footer on every page: `_quarto.yml` sets `page-footer: border: false`, after which the stylesheet of the existing pages differs from `main` only by one sidebar-only rule.

**D27. Wide display equations.** The notes' text block is 45 em and many displays fill it. The text column is 880 px in the grid (≈ 46 em at the 17 px base size on wide screens); on narrower windows `course.js: fitDisplayMath` sets a display that overflows slightly a little smaller (never below 80 %), and only what still overflows scrolls sideways inside its own box, with a fade at the hidden edge. Inline formulas wider than the line scroll in place (`dg-math-wide`). The page itself never scrolls sideways (asserted at 390 px by `test_page_script.mjs`).

**D28. `docs/` is committed at milestones only** (end of pilot, end of each batch of bulk units, final), not with every unit: it is 11 MB of render output and every render touches all 73 pages. Source and generated `.qmd` are committed with each unit. Always stage with `git -c core.fileMode=false add <paths>` so the mode-only changes of existing files (D22) are not recorded.

## Planned (design fixed, not built yet)

**D24. Fidelity check** (`_port/tools/fidelity.py`): an implementation independent of `render.py` reduces the LaTeX source to an ordered stream of (a) math strings with whitespace removed and (b) text words with commands stripped; the generated pages are reduced to the same stream from their HTML (footnote bodies spliced in at their marks, `dg-web` elements and generated numbers ignored); the two are diffed. Accepted differences are listed one by one in `_port/fidelity_allow.json` (hidden `\DLC` notes, "in preparation" markers, the four math rewrites of D7, text inside TikZ pictures, which lives in the SVG). Built in unit B6 (2026-11-16): the tool cuts the source at the page boundaries (D3, D51, D52) and diffs each piece with its page (footnote bodies at their marks; `\footnotetext` at the end of its page; references as the numbers of `main.aux`, citations as natbib's text). The allow-list has two kinds of entry, each with its reason: `source` (a construct whose words live elsewhere: TikZ pictures, the cover, dedication and About-the-Author overlays, the roadmaps' saved boxes, `\DLC`), matched by file, kind and a content fingerprint so that edits above it do not make it stale; and `diff` (page + exact tokens: "in preparation" markers, the D7 rewrites, the landing and About-the-Author texts). An entry that matches nothing fails the check, as does a construct the tool does not know (`TEACH file:line`). The List of Figures entries are not compared (they repeat the captions, which are compared where the figures are); the Bibliography is compared with `main.bbl`.

**D25. Cross-reference previews** (built in the pilot, `course.js`): on hover/focus of `a.dg-xref`, fetch the target page once, take the element with that id (equation, figure, list item, footnote, or heading + first paragraph), show it in the same popover as footnotes and typeset it.

## Measured

**Math engines** (`node _port/tools/math_check.mjs --engine all`, 5356 expressions, 3047 distinct; 2026-11-14):

| Engine | Failures | What fails |
|---|---|---|
| MathJax 3.2.2 (chosen) | 1 | the `tabular` inside display math in §4.1.2 (`Coordinates_TpM.tex` ~l.299) |
| MathJax 4.1.3 | 1 | the same `tabular` |
| KaTeX 0.19.1 | 9 | that `tabular` + 8 arrays with `@{..}` column specs; no `\xlongrightarrow`; `\coloneq` prints ":−" |

MathJax 3 is kept (Quarto's default, well known, same failure count as 4). Config-level fixes applied in `mathjax-config.js`: `\coloneq` → `\coloneqq` (TeX Live 2023 mathtools prints ":=" for both; MathJax 3 would print ":−"); `\xlongrightarrow[below]{above}` → `\xrightarrow[below]{\;above\;}` (closest arrow length to LaTeX's: within 0.1 em on typical labels). `tex-chtml-full` already contains every extension, so there is no `loader.load` (it throws in the browser). `matchFontHeight: false` keeps math at the text size.
Known residual differences with MathJax 3, to revisit only if the author minds: in the 8 arrays with `@{\quad}` / `@{\qquad}` column specs the gap beside the vertical rule is 0.5 em instead of 1–2 em (MathJax 4 renders `@{}` exactly; switching engines is the fix, not rewriting math). The `tabular` needs the converter (unit B2): emit it as an HTML table whose cells keep their `$…$` source.
In the browser `tex-chtml-full` enables `noerrors`/`noundefined`, so a broken expression shows as raw source or red text, not as an error node: `math_check.mjs` (Node, those two packages off) is the check that catches them.

**Runic symbols** verified in the browser (screenshots at 3× of §7.2): correct glyphs from the notes' font inline, in display math, in subscripts (`L_{ᚱ^{-1}([a,b])}`, `γ_ᛊ`, `ᛊ=0` limits) and inside the TikZ figure 7.1.

**Figures** (`python3 _port/tools/test_figures.py` prints the table). `pdftocairo -svg` is correct for the 5 small 2D plots (67–320 kB); `dvisvgm --pdf` drops matplotlib's text and is never used. The 14 mesh-heavy 3D plots are 0.6–4 MB as SVG and become WebP (1800 px wide, q 80: 40–470 kB each). TikZ → SVG with `dvisvgm --no-fonts --exact-bbox --optimize`: roadmaps 360–715 kB, others ~100 kB; needs `\def\pgfsysdriver{pgfsys-dvisvgm.def}` and `\NewCommandCopy` for the `\ref` wrapper (hyperref's `\ref` is robust, `\let` loops). All 31 figures of the 72 converted pages: 5.8 MB (once more in `docs/`). The Einstein–Hilbert flowchart (B3, D50): 555 kB. `RASTER_PDF_PX`, `WEBP_Q`, `SVG_MAX` in `figures.py` are the knobs; they are part of the cache key.
The four worked-example PDFs that are whole A4 pages keep their margins, as `\includegraphics` shows them in the PDF (no cropping: it would change their relative size).

**Quarto** (1.9.37): directories starting with `_` are not rendered (`_port/`, `_generated/`); raw-inline headings appear in the page outline; raw-HTML text is indexed by the site search per section; root-absolute `/notes/...` URLs in the head include are rewritten to relative ones; MathJax is added by Quarto to every page, so we only pin its URL. `quarto render notes/diffgeo-gr` takes ~1 min for 73 pages. The scratch LaTeX build takes ~4 min; the converter ~10 s with a warm figure cache (~3 min cold).

## Phase 2 (REDESIGN.md)

Where a decision below contradicts D1–D28, the later one wins; what it replaces is named.

**D29. The course pages leave Quarto's page templates: the converter writes complete HTML pages, and Quarto only copies them.** (Replaces D6 and D13; D26 becomes moot.)
Why: the chosen design (D30) needs its own page shell (course tree with the outline inside, sidenote margin, course bar, theme switch, own typeface). Inside a Quarto page that means overriding Bootstrap's `darkly` theme and Quarto's sidebar, margin, footnote and anchor scripts on every page (D26 lists what already had to be worked around), and a light theme inside a compiled dark Bootstrap bundle. Writing the page ourselves removes pandoc from between the converter and the reader (the HTML published is exactly what `render.py` wrote), drops ~300 kB of Bootstrap/Quarto assets per page, and makes a course build take ~10 s instead of 1–2 min, which matters for every later unit.
How (tested on Quarto 1.9.37 in a scratch project, 2026-11-15):
- Generated pages are `notes/diffgeo-gr/**/*.html` (complete documents, committed, with the "generated, do not edit" comment). `_quarto.yml` lists `notes/diffgeo-gr/**` under `project: resources`, so EVERY `quarto render` (full or single file) copies them to `docs/notes/diffgeo-gr/` verbatim. A full render cleans `docs/` first and the pages come back from the committed copies: no hook, no scratch LaTeX build and no Node are needed for that, so a fresh clone can render the site. (Files and directories starting with `_` inside the course directory are copied too by the glob; keep generated intermediates out of it or accept the copy.)
- Quarto does not render `.html` files, so the course no longer appears in Quarto's `search.json` and `sitemap.xml`. A project `post-render` script (`_port/tools/post_render.py`, standard library only, reads only committed files) appends the course's entries to both. `QUARTO_PROJECT_OUTPUT_DIR` gives the output directory.
- The navbar entry becomes `href: notes/diffgeo-gr/index.html` (a plain link; verified to render as `./notes/diffgeo-gr/index.html`). The `metadata-files: notes/diffgeo-gr/_sidebar.yml` include and the `page-footer: border` workaround are removed, after which the existing pages' Bootstrap bundle no longer carries the sidebar rule.
- The site navbar on course pages is a replica (same links, same look): the links are read from the `website: navbar: left` block of `_quarto.yml` by the converter, the look is CSS written from measurements of the Quarto navbar (`_port/design/measure_nav.mjs`; 82 px tall at ≥ 992 px, 69 px below, `rgba(8,12,22,.82)` on `#0b1220`, Lato 17 px, links `#dbe7ff`). `check.sh` compares a screenshot of both navbars so they cannot drift apart.
- One command still builds everything: `_port/build.sh --site` (scratch LaTeX build, converter, `quarto render`). `quarto render` alone is also safe.
- Addresses do not change (`docs/notes/diffgeo-gr/<chapter>/<section>.html`), so nothing needs a redirect. `_port/pilot_addresses.txt` lists the 73 addresses that existed at the pilot; `check.sh` verifies each still exists.
What stays: `source.py`, `texparse.py`, `render.py` (the body HTML), numbering (D5), figures (D10), `labels.json`, the interactive core (D15). What goes: the `.qmd` pages, `_metadata.yml`, `_sidebar.yml`, `_head.html`, `_generated/*.qmd`, `index.qmd` (the landing page becomes a template in `_port/convert/` with the same generated fragments).

**D30. Design direction A, "Paper"** (`DESIGN.md` § 3; chosen by Claude under the author's delegation, 2026-11-15). The prototype in `_port/design/proto/` (`shell.css` + `a.css` + `proto.js`) is the pattern: milestone 1 turns it into the real `assets/course.css` / `course.js` and the converter's page template. The prototypes stay in the repo as the record of the comparison; they are not part of the build.

**D31. Typeface.** Text and headings in New Computer Modern 10 Book/Bold (+ italics): the same design as the notes' Latin Modern, with heavier strokes made for screens, which Latin Modern is too thin for. The converter subsets the four TeX Live fonts (`/usr/share/texlive/texmf-dist/fonts/opentype/public/newcomputermodern/NewCM10-*.otf`) to Latin + punctuation with fontTools (already on this machine; `layout_features` kern, liga, smcp, c2sc, onum, lnum) and writes WOFF2 to `notes/diffgeo-gr/assets/fonts/` (≈ 33 kB each, committed, so a machine without TeX Live or fontTools reuses them). Licence: GUST Font License (redistribution and subsetting allowed; noted in `REVIEW.md`). Interface text is Lato, loaded as the rest of the site loads it. Rule: the text face is only ever used for the notes' own words; every web-layer word is in Lato (D14's "visibly separate", made typographic).

**D32. Light by default, dark on request.** `:root` carries the light palette; `:root[data-theme="dark"]` the dark one (DESIGN § 4). A script in the `<head>` sets `data-theme` from `localStorage['dg-theme']` before first paint. No automatic switch on `prefers-color-scheme`: the paper surface is the design, and the site around it is dark anyway, so the OS setting is not a useful signal here. Cheap to change (one line in the head script). Figures keep their white paper in both themes (D10d).

**D33. Footnotes** are sidenotes from 1000 px (same text and number, in the margin at the height of the mark; pushed down if they would overlap), and popover + list at the foot of the page below that (D11). The list at the foot is always in the HTML (it is the no-JS and print form); the script builds the margin copies.

**D34. Math engine: MathJax 4 if it passes, decided by a check, not by taste.** Reasons to move: its default font is New Computer Modern Math, the family of the text face (D31), and it renders the `@{…}` column specs of the eight arrays as LaTeX does (see "Measured"). Unit R6 loads MathJax 4.1.x on every page in the browser and must show: 0 failures in `math_check.mjs --engine mathjax4` beyond the known `tabular` (which unit B2 removes); runes correct inline, in display, in sub/superscripts (the D8 screenshots repeated); no page slower to typeset than with 3.2.2 by more than 30 %; the weight budget of DESIGN § 4 holds. If any of these fails, stay on 3.2.2 and record why here.
Result (R6, 2026-11-15): **the site stays on MathJax 3.2.2**: MathJax 4.1.3 (the latest 4.1.x) fails the timing criterion on the light pages; the other three hold. (1) `math_check.mjs --engine mathjax4` with a MathJax 4 config: 3047 expressions, 1 failure (the known `tabular`). **D48. `tabular` → an HTML table whose cells are the notes' text (unit B2; `_port/convert/tables.py`).** A `tabular` is text mode in LaTeX, so it becomes a `<table>` whose cells go through the same parser and renderer as every other sentence of the notes (their `$..$` stay the notes' math source, typeset inline). This also covers the one tabular written inside display math (`\[ \begin{tabular}..\end{tabular} \]`, §4.1.2): a display whose whole content is one tabular is rendered as a centred table that ends the paragraph's `<p>` (a table cannot sit inside a `<p>`). That is not a rewrite of math (D7 keeps its four): MathJax never sees it, and `math_check` now checks the cells' inline formulas instead of one failing expression. Structure comes only from the source: column spec `l c r p{w} | @{..}` (alignment; `p` columns top-aligned at width w; `|` a 1 px rule in the text colour; `@{}` / `@{\hspace{w}}` replace the whole gap between two columns, otherwise LaTeX's 6 pt `\tabcolsep` on each side); rows end at top-level `\\`; `\\[dim]` deepens the row's strut by dim as array.sty does (an invisible `span.dg-row-strut` 0.3 em + dim deep in the row's first cell, so a row that is already deep, like §4.1.2's `\dfrac` row, absorbs part of it: a plain padding made that table visibly looser than the PDF); `\hline` is a rule above the next row (or below the last); rows are `\arraystretch` × the 1.2 em baselineskip (line-height 1.2, the stretch from `\renewcommand{\arraystretch}{x}` as padding, `--dg-arraystretch`); `l c r` cells never wrap (`white-space: nowrap`, as in LaTeX), only `p{w}` cells do. A table slightly wider than the column is set a little smaller exactly like a display equation (D27, never below 80 %, `course.js: fitDisplayMath`); B.21's table needs 96 % at 1440 px, the web face being a little wider than the PDF's. What still overflows scrolls in its box, which is then keyboard-focusable (axe `scrollable-region-focusable`). Lengths are converted at the notes' 10 pt type (1 pt = 0.1 em, `\textwidth` = the renderer's text width), so gaps and widths keep their proportion to the text. A first row followed by an `\hline` is the header (`<th scope="col">`): that rule is how the PDF marks it, and screen readers then announce the column names; no other row becomes a header and no cell is restyled (a `\textbf` cell stays bold because the notes wrote it, `th` itself is not bold). Scrolling boxes show the D45 edge shadows. Anything outside this subset (another column type, a position argument, nested tabular, `\hline` inside a row, more cells than columns) stops the page with `file:line`. `main.port` records no tables (none is in a `table` float), so nothing is numbered. Tested in `tools/test_converter.py` (now part of `check.sh`), including the copyright page's spec (`@{}l@{\hspace{10pt}}p{\dimexpr\textwidth-3.25cm\relax}@{}`, unit B4).
